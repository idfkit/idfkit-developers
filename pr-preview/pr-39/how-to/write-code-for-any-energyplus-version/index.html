    How to write code for any EnergyPlus version, or a range of them¶

    This guide is Python only. TypeScript reaches the same result by leaving a document unparameterised, or by parameterising it with one release's type map; see static types generated from the schema.

    This guide shows you how to annotate functions and modules so that pyright checks them against the EnergyPlus releases they will actually meet: the latest release only, every supported release, or a range such as "9.6 and later". It assumes the project already runs pyright in strict mode; if not, start with how to check idfkit code.

    Differs in Python

    Static types generated from the schema exists in both libraries and does not behave the same way in Python. The ledger records it as Python partial, JavaScript complete, and what differs is stated here rather than left to be discovered.

    Coverage differs, and the difference is visible to anyone not on the newest release. The Python stub set is generated for one EnergyPlus version at a time and is currently shipped for 26.1.0 only, so a model loaded at 9.4 gets the 26.1 field names and choice lists from the editor. The TypeScript type maps are emitted per version and selected by the caller, who parameterises the document with the map for the version being read, so an older model is typed as that older model or is left untyped rather than mistyped.

    Application differs too. Python's stubs apply implicitly to every document. TypeScript's are opt-in by construction: an unparameterised document stays untyped, which is what version-generic code needs.

    The full entry, including the vocabulary this capability owns, is on the capability parity page.

    Pick the document type to annotate with¶

    The annotation on a document parameter is a statement about which releases the code handles. Pick the narrowest one that is true:

    The code handles models that are Annotate the document as For example
    created with new_document(), or loaded and known to be the latest release, including models you migrated to it first IDFDocument, or leave it inferred a script that builds a new model; a pipeline that runs migrate on every input before anything else
    of one known release that release's type, such as IDFDocumentV9_4, given with as_version a tool for a portfolio of 9.4 models; see how to type a model for its EnergyPlus version
    of whatever release the caller hands over AnyIDFDocument a reusable function, a library, a command-line tool that opens users' files
    of a range of releases a union of release types code that needs Space, which arrived in 9.6

    Two consequences decide the hard cases:

    • load_idf returns IDFDocument whatever the file's release, because the checker cannot read the file. Annotating a function IDFDocument is a claim that its callers only pass latest-release models; nothing checks that claim when a 9.4 file is loaded. If the code may see an older file, annotate AnyIDFDocument.
    • AnyIDFDocument accepts every document: one from load_idf or new_document(), and any document typed with as_version. IDFDocument accepts only the latest release, and pyright rejects a 9.4 document passed to it. Taking AnyIDFDocument therefore costs callers nothing, and costs the function every name some release lacks.

    Declare the package's choice in one place¶

    In a package, make the choice from the table once. Put it in one private module and annotate everything else with the names it exports, so that supporting a different set of releases later is an edit to that module alone. The module holds four things:

    • SUPPORTED, a tuple of the release types, for as_version;
    • Model, an alias for the same releases, for annotations, and ModelT, a TypeVar bound to it, for functions that return the model they were given;
    • the object classes, imported under the names the package uses;
    • as_model, the one function that gives a loaded model the package's type.

    This package supports 9.6 and later, the releases that have Space:

    # mypkg/_idf.py: the releases this package supports, in one module.
from typing import TYPE_CHECKING, TypeAlias, TypeVar

from idfkit import IDFDocument
from idfkit.document import AnyIDFDocument
from idfkit.versioned import (
    IDFDocumentV9_6,
    IDFDocumentV22_1,
    IDFDocumentV22_2,
    IDFDocumentV23_1,
    IDFDocumentV23_2,
    IDFDocumentV24_1,
    IDFDocumentV24_2,
    IDFDocumentV25_1,
    IDFDocumentV25_2,
    IDFDocumentV26_1,
    as_version,
)

# The same releases twice: a tuple for as_version, an alias for annotations. Keep them together.
SUPPORTED = (
    IDFDocumentV9_6,
    IDFDocumentV22_1,
    IDFDocumentV22_2,
    IDFDocumentV23_1,
    IDFDocumentV23_2,
    IDFDocumentV24_1,
    IDFDocumentV24_2,
    IDFDocumentV25_1,
    IDFDocumentV25_2,
    IDFDocumentV26_1,
    IDFDocument,
)
Model: TypeAlias = (
    IDFDocumentV9_6
    | IDFDocumentV22_1
    | IDFDocumentV22_2
    | IDFDocumentV23_1
    | IDFDocumentV23_2
    | IDFDocumentV24_1
    | IDFDocumentV24_2
    | IDFDocumentV25_1
    | IDFDocumentV25_2
    | IDFDocumentV26_1
    | IDFDocument
)
ModelT = TypeVar("ModelT", bound=Model)  # for functions that return the model they were given

if TYPE_CHECKING:
    # Object classes for the same releases. Any<Class> covers every supported release that has
    # the type; for a latest-only package, import the plain classes (Zone, Space) instead.
    from idfkit.document import AnySpace as Space
    from idfkit.document import AnyZone as Zone


def as_model(doc: AnyIDFDocument) -> Model:
    """Type a loaded model for the supported releases; raise TypeError for any other."""
    return as_version(doc, SUPPORTED)

    The rest of the package annotates with Model, Zone and Space, and calls as_model at its public entry points:

    # mypkg/zones.py: annotates with the package's names, never with idfkit's.
def zones_without_spaces(model: Model) -> list[str]:
    spaced = {space.zone_name for space in model["Space"]}
    return [zone.name for zone in model["Zone"] if zone.name not in spaced]


def ceiling_height(zone: Zone) -> float | None:
    height = zone.ceiling_height
    return height if isinstance(height, float) else None


def space_type(space: Space) -> str | None:
    return space.space_type


def tag_model(model: ModelT) -> ModelT:
    for space in model["Space"]:
        space.space_type = space.space_type or "General"
    return model


# The package's public entry point: any loaded model, narrowed once.
def report(doc: AnyIDFDocument) -> list[str]:
    return zones_without_spaces(as_model(doc))

    To change what the package supports, edit only the first module:

    To support SUPPORTED Model Object classes as_model
    every release remove it AnyIDFDocument AnyZone as Zone, ... return doc
    a range, as above the range's types their union AnyZone as Zone, ... as_version(doc, SUPPORTED)
    the latest only (IDFDocument,) IDFDocument Zone, Space, ... as_version(doc, SUPPORTED)

    Then run pyright. It reports each line the new choice no longer allows, so the rest of the change is a list it gives you. Widening this package to every release, for example, reports the two lines that read model["Space"]:

    error: Could not access item in TypedDict
    "Space" is not a defined key in "IDFDocumentAllVersions[bool]" (reportGeneralTypeIssues)

    Keep SUPPORTED and Model next to each other: they list the same releases twice, and nothing checks that they agree. Keep the --targets of idfkit check in step too, since they live in the CI workflow or the pre-commit configuration rather than in Python; see how to check idfkit code.

    Under mypy, as_model is reported as returning the wrong type for a range, because mypy collapses the tuple's union. A package that checks with mypy is better served by AnyIDFDocument or a single release type.

    Accept a model of any release¶

    Annotate the document AnyIDFDocument and let everything you reach through it be inferred:

    from idfkit import load_idf
from idfkit.document import AnyIDFDocument
from idfkit.versioned import IDFDocumentV9_4, as_version


def zone_ceiling_heights(doc: AnyIDFDocument) -> dict[str, float | None]:
    """Each zone's ceiling height, for a model of any supported release."""
    heights: dict[str, float | None] = {}
    for zone in doc["Zone"]:  # inferred from the document; no Zone annotation needed
        height = zone.ceiling_height  # float | "Autocalculate" | "" | None, as every release reads it
        heights[zone.name] = height if isinstance(height, float) else None
    return heights


zone_ceiling_heights(load_idf("model.idf"))  # a latest-release model
zone_ceiling_heights(as_version(load_idf("legacy.idf"), IDFDocumentV9_4))  # a 9.4 model

    Through AnyIDFDocument:

    • doc["Type"] and accessors such as doc.zones accept the 789 object types every supported release defines. Space and SpaceList, new in 9.6, are not among them. Your editor still suggests them after doc[", because a latest-release document is part of the union, but choosing one is an error.
    • Each object offers only the fields every release has. A field one release renamed, such as People.zone_or_zonelist_or_space_or_spacelist_name (zone_or_zonelist_name before 9.6), is an error to read or assign.
    • update() keywords and values are checked the same way.

    Import AnyIDFDocument from idfkit.document or idfkit.versioned; both check equally fast. idfkit's own functions (save_idf, simulate, the geometry and zoning helpers) take AnyIDFDocument, so any document passes to them, and the ones that return the document they were given, such as expand_objects and doc.copy(), return the type they received.

    Pass objects to helper functions¶

    Annotate a helper's object parameter with the class for the releases the code handles:

    • In code for any release, use Any<Class>: AnyZone, AnyConstruction, AnyWaterHeaterMixed, and so on. It accepts that object from a document of any release, including one reached through AnyIDFDocument, and offers what every release has, by the same rules as AnyIDFDocument.
    • In code for the latest release only, use the plain class, such as Zone. It rejects a zone of any other release: a 9.4 zone is a Zone_v8_9_to_v9_4.
    from typing import TYPE_CHECKING

from idfkit import load_idf
from idfkit.document import AnyIDFDocument
from idfkit.versioned import IDFDocumentV9_4, as_version

if TYPE_CHECKING:
    # The object classes exist only in the stubs: import them for the type checker alone.
    from idfkit.document import AnyConstruction, AnyZone


def ceiling_height(zone: AnyZone) -> float | None:
    """A zone's ceiling height as entered, for a zone of any release."""
    height = zone.ceiling_height  # only fields every release has
    return height if isinstance(height, float) else None


def layer_names(construction: AnyConstruction) -> list[str]:
    return [name for name in (construction.outside_layer, construction.layer_2) if name]


def tall_zones(doc: AnyIDFDocument, minimum: float) -> list[str]:
    return [zone.name for zone in doc["Zone"] if (ceiling_height(zone) or 0.0) >= minimum]


ceiling_height(load_idf("model.idf")["Zone"]["Office"])  # a latest-release Zone
ceiling_height(as_version(load_idf("legacy.idf"), IDFDocumentV9_4)["Zone"]["Office"])  # a 9.4 zone

    Import the classes from idfkit.document inside if TYPE_CHECKING:; they do not exist at run time. Every object type of the latest release has an Any<Class>, whether or not its declaration changed between releases, so you never need to know which types did. A type a later release removed has none: DistrictHeating, gone after 23.1, is reached through its range class from idfkit.versioned, DistrictHeating_v8_9_to_v23_1, imported the same way. Passing the wrong kind of object is reported against the class:

    error: Argument of type "Material" cannot be assigned to parameter "zone" of type "AnyZone" in function "ceiling_height"

    On an Any<Class>:

    • Extensible groups are typed, such as AnyBuildingSurfaceDetailed.vertices. A group whose fields changed between releases follows the same read and write rule as a field: AnyOutputTableAnnual.variable_details[0].digits_after_decimal reads as float | int | None, and assigning 2.5 is an error because 22.2 and later take an integer.
    • A group that some release lacks entirely is not offered. AnyScheduleYear and AnyPlantEquipmentList are among the few types affected. Reach those groups through the release's own type, or with item access.

    The rules also apply when idfkit itself changes. Any<Class> covers the releases the installed idfkit supports, so it narrows when idfkit adopts a new EnergyPlus release that renames or drops a field. AnyPeople shows the effect: 9.6 renamed zone_or_zonelist_name, so AnyPeople has neither the old name nor the new one, and reading either is reported like any other unknown field. A future EnergyPlus rename does the same to fields your code uses today. Run pyright after upgrading idfkit, and treat such errors as the new release's changes reaching your code.

    Code that needs nothing beyond IDFObject can still take an IDFObject, which accepts any object of any release, untyped, or take the document and reach the objects itself.

    Read and write a field whose values changed¶

    When a field accepts different values in different releases, the value you read and the value you may write have different types through AnyIDFDocument:

    • Reading gives what a file of any release can contain: every release's values together. WaterHeater:Mixed.heater_fuel_type reads as str | None, because 8.9 to 9.2 accept any string there.
    • Writing, by assignment or update(), accepts only what every release accepts. For the heater fuel that is Coal, Diesel, Electricity, FuelOilNo1, FuelOilNo2, Gasoline, NaturalGas, OtherFuel1, OtherFuel2, Propane, or None. "DistrictHeatingWater" (which 9.3 to 23.1 reject) and "Steam" or "DistrictHeating" (which 23.2 and later reject) are errors to write.
    • When no value is valid in every release, only None, which clears the field, is writable.
    from idfkit.document import AnyIDFDocument


def electrify_water_heaters(doc: AnyIDFDocument) -> list[str]:
    """Switch every gas-fired WaterHeater:Mixed to electricity; return the names changed."""
    changed: list[str] = []
    for heater in doc["WaterHeater:Mixed"]:
        fuel = heater.heater_fuel_type  # str | None: 8.9 to 9.2 accept any string here
        if fuel is not None and fuel.lower() == "naturalgas":
            heater.heater_fuel_type = "Electricity"  # a value every release accepts
            changed.append(heater.name)
    return changed

    Do not treat the type you read through AnyIDFDocument as a closed list. Compare it with the values you handle and leave a branch for anything else. A match that ends in assert_never cannot pass there, because the read type includes str:

    error: Argument of type "str" cannot be assigned to parameter "arg" of type "Never" in function "assert_never"

    To handle every value exhaustively, restrict the function to releases whose choices are fixed; see handle every value of a field.

    The checker is the only guard on writes. Assigning a value the model's release rejects does not raise at run time: a 9.4 document stores "DistrictHeatingWater" without complaint, and EnergyPlus rejects it later.

    Reach an object type some releases lack¶

    When the code genuinely serves every release, take the collection by name with get_collection. It accepts any type name and returns IDFCollection[IDFObject], untyped, and for a release without the type it is empty:

    from idfkit.document import AnyIDFDocument


def space_names(doc: AnyIDFDocument) -> list[str]:
    """Name every Space, or none for a release before 9.6, which had no Space."""
    # get_collection takes any type name and returns IDFCollection[IDFObject], so it
    # type-checks against every release. For a release without the type it is empty.
    return [space.name for space in doc.get_collection("Space")]

    When the code needs the type's fields typed, narrow the model to the releases that have the type, and pass the objects to helpers annotated with the type's Any<Class>. AnySpace accepts a Space of any release that has one, 9.6 and later. Keep the public signature AnyIDFDocument, so the decision about older models lives in one place:

    from typing import TYPE_CHECKING

from idfkit import IDFDocument
from idfkit.document import AnyIDFDocument
from idfkit.versioned import (
    IDFDocumentV9_6,
    IDFDocumentV22_1,
    IDFDocumentV22_2,
    IDFDocumentV23_1,
    IDFDocumentV23_2,
    IDFDocumentV24_1,
    IDFDocumentV24_2,
    IDFDocumentV25_1,
    IDFDocumentV25_2,
    IDFDocumentV26_1,
    as_version,
)

if TYPE_CHECKING:
    from idfkit.document import AnySpace

SINCE_9_6 = (
    IDFDocumentV9_6,
    IDFDocumentV22_1,
    IDFDocumentV22_2,
    IDFDocumentV23_1,
    IDFDocumentV23_2,
    IDFDocumentV24_1,
    IDFDocumentV24_2,
    IDFDocumentV25_1,
    IDFDocumentV25_2,
    IDFDocumentV26_1,
    IDFDocument,
)


def label_spaces(doc: AnyIDFDocument, space_type: str) -> int:
    """Public API: takes a model of any release. Returns how many spaces were labelled."""
    if doc.version < (9, 6, 0):
        return 0  # the one place that decides what a model without Space gets
    recent = as_version(doc, SINCE_9_6)
    for space in recent["Space"]:
        _label(space, space_type)
    return len(recent["Space"])


def _label(space: AnySpace, space_type: str) -> None:
    """Takes a Space of any release that has one; no version logic here."""
    space.space_type = space_type

    _label holds no version logic, and label_spaces is the only line that knows Space arrived in 9.6. Return early, as here, or raise if an older model is a caller's mistake. A Space is reached only through a document of a release that has it: doc["Space"] through AnyIDFDocument is an error, and the objects get_collection("Space") returns are IDFObject, which pyright does not accept as an AnySpace. Narrowing is covered in narrow a model of unknown release into a range.

    Restrict a function to a range of releases¶

    Name the releases in a type alias and annotate with it. Through the union, a lookup is typed for each member, and only what every member has is offered:

    from typing import TypeAlias

from idfkit import IDFDocument
from idfkit.versioned import (
    IDFDocumentV9_6,
    IDFDocumentV22_1,
    IDFDocumentV22_2,
    IDFDocumentV23_1,
    IDFDocumentV23_2,
    IDFDocumentV24_1,
    IDFDocumentV24_2,
    IDFDocumentV25_1,
    IDFDocumentV25_2,
    IDFDocumentV26_1,
)

# Every release from 9.6, the one that introduced Space, to the latest.
Since9_6: TypeAlias = (
    IDFDocumentV9_6
    | IDFDocumentV22_1
    | IDFDocumentV22_2
    | IDFDocumentV23_1
    | IDFDocumentV23_2
    | IDFDocumentV24_1
    | IDFDocumentV24_2
    | IDFDocumentV25_1
    | IDFDocumentV25_2
    | IDFDocumentV26_1
    | IDFDocument
)


def space_areas(doc: Since9_6) -> dict[str, float | None]:
    """Each Space's floor area, as entered. Typed through every release from 9.6 on."""
    areas: dict[str, float | None] = {}
    for space in doc["Space"]:  # a typed Space of whichever release the document is
        area = space.floor_area
        areas[space.name] = area if isinstance(area, float) else None
    return areas

    Here doc["Space"] is IDFCollection[Space_v9_6_to_v22_1] | IDFCollection[Space_v22_2_to_v26_1] | IDFCollection[Space], so space.floor_area is checked against each.

    The same pattern covers the other ranges. Pick the members from IDFDocumentV8_9 to IDFDocumentV26_1, plus IDFDocument for 26.2:

    • From a release on: that release's type through IDFDocument, as above.
    • Before a release: IDFDocumentV8_9 up to the last release before it. Before9_6 would be IDFDocumentV8_9 | ... | IDFDocumentV9_5.
    • Between two releases: the types from the first to the last.

    At the call site, a latest-release document and any member typed with as_version pass. A document outside the range is rejected, with the first few differences listed:

    error: Argument of type "IDFDocumentV9_4[bool]" cannot be assigned to parameter "doc" of type "Since9_6" in function "space_areas"

    A document typed for a range is still a document of some release, so it passes to every function that takes AnyIDFDocument.

    Writes through a range follow the same rule as through AnyIDFDocument: pyright accepts a value only if every release in the union accepts it. Through IDFDocumentV9_4 | IDFDocument, heater_fuel_type = "NaturalGas" passes, while "DistrictHeatingWater" is reported against 9.4's class and "DistrictHeating" against the latest:

    error: Cannot assign to attribute "heater_fuel_type" for class "WaterHeaterMixed_v9_3_to_v23_1"
error: Cannot assign to attribute "heater_fuel_type" for class "WaterHeaterMixed"

    mypy reports the same value passed to update(), but misses both assignments through a union of release types. If the project runs mypy, write changed fields in range code with update().

    The annotation is a claim the checker holds callers to; nothing checks it when the code runs. To guard against a caller that passed an unchecked load_idf result of another release, narrow with as_version as in the next section.

    Hand the caller's type back from a range function¶

    A function that returns the document it was given loses the caller's type if it is annotated with the union: pyright infers the whole union as the return type, and mypy, which does not infer return types, gives Any. Bind a TypeVar to the union instead:

    from typing import TypeVar

from idfkit import load_idf
from idfkit.versioned import IDFDocumentV26_1, IDFDocumentV26_2, as_version

# 26.1 and later. Bound to the union, so each call hands back the caller's own type.
Since26_1 = TypeVar("Since26_1", bound="IDFDocumentV26_1 | IDFDocumentV26_2")


def use_district_steam(doc: Since26_1) -> Since26_1:
    for heater in doc["WaterHeater:Mixed"]:
        heater.heater_fuel_type = "DistrictHeatingSteam"  # both releases accept it
    return doc


latest = use_district_steam(load_idf("model.idf"))  # IDFDocument, which is IDFDocumentV26_2
older = use_district_steam(as_version(load_idf("older.idf"), IDFDocumentV26_1))  # IDFDocumentV26_1

    latest is IDFDocument[Literal[True]] and older is IDFDocumentV26_1[bool] under pyright. A 9.4 document is still rejected, by both checkers:

    error: Argument of type "IDFDocumentV9_4[bool]" cannot be assigned to parameter "doc" of type "Since26_1@use_district_steam" in function "use_district_steam"
error: Value of type variable "Since26_1" of "use_district_steam" cannot be "IDFDocumentV9_4[Any]"  [type-var]

    The first line is pyright's, the second mypy's. IDFDocumentV26_2 is IDFDocument, so a plain load_idf result passes without as_version.

    Handle every value of a field¶

    Through a range in which every release lists the field's choices, the value reads as those choices, and a match over them can be checked as exhaustive. From 23.2 on, heater_fuel_type reads as twelve choices or None:

    from typing import TypeAlias

from typing_extensions import assert_never

from idfkit import IDFDocument
from idfkit.versioned import (
    IDFDocumentV23_2,
    IDFDocumentV24_1,
    IDFDocumentV24_2,
    IDFDocumentV25_1,
    IDFDocumentV25_2,
    IDFDocumentV26_1,
)

# Through these releases heater_fuel_type reads as 12 choices or None, so a match can be exhaustive.
Since23_2: TypeAlias = (
    IDFDocumentV23_2
    | IDFDocumentV24_1

def is_district_heated(doc: Since23_2, heater_name: str) -> bool:
    fuel = doc["WaterHeater:Mixed"][heater_name].heater_fuel_type
    match fuel:
        case "DistrictHeatingWater" | "DistrictHeatingSteam":
            return True
        case (
            "Coal"
            | "Diesel"
            | "Electricity"
            | "FuelOilNo1"
            | "FuelOilNo2"
            | "Gasoline"
            | "NaturalGas"
            | "OtherFuel1"
            | "OtherFuel2"
            | "Propane"
            | None
        ):
            return False
        case _:
            assert_never(fuel)  # reported if a choice is left unhandled

    Leave a choice out and pyright names it at the assert_never call, for example Argument of type "Literal['Propane']" cannot be assigned to parameter "arg" of type "Never". Add 9.4 to the range and the read type gains its own choices ("DistrictHeating", "Steam"), which the match then has to handle too.

    Narrow a model of unknown release into a range¶

    A function that takes AnyIDFDocument and wants to call space_areas has to establish that the model is 9.6 or later. Pass as_version a tuple of the range's release types, as you would pass isinstance a tuple of classes:

    from idfkit.document import AnyIDFDocument
from idfkit.versioned import as_version

# A tuple of the same release types, for as_version; the alias above is for annotations.
SINCE_9_6 = (
    IDFDocumentV9_6,
    IDFDocumentV22_1,
    IDFDocumentV22_2,
    IDFDocumentV23_1,
    IDFDocumentV23_2,
    IDFDocumentV24_1,
    IDFDocumentV24_2,
    IDFDocumentV25_1,
    IDFDocumentV25_2,
    IDFDocumentV26_1,
    IDFDocument,
)


def report_spaces(doc: AnyIDFDocument) -> dict[str, float | None]:
    if doc.version < (9, 6, 0):
        return {}  # a model before 9.6 has no Space objects
    return space_areas(as_version(doc, SINCE_9_6))  # checked again at run time

    Pyright types the result as the union of the tuple's types, IDFDocumentV9_6[bool] | IDFDocumentV22_1[bool] | ... | IDFDocument[bool]. as_version checks the version again at run time; without the early return, a 9.4 model would raise:

    TypeError: The document is EnergyPlus 9.4.0, not one of 9.6.0, 26.2.0, so it cannot be typed as IDFDocumentV9_6 | IDFDocument

    That message is from a two-type tuple; a longer tuple lists every release in it.

    Keep the tuple for as_version and the alias for annotations. The other spellings do not work for this:

    • The alias, as_version(doc, Since9_6), is rejected by pyright: No overloads for "as_version" match the provided arguments.
    • An inline union, as_version(doc, IDFDocumentV9_6 | IDFDocument), works under pyright and at run time, but mypy rejects it.
    • Under mypy, a tuple is accepted but its union collapses to what all its releases share: recent["Space"] is IDFCollection[AnySpace], and fields that differ between the releases are reported as missing.
    • isinstance(doc, IDFDocumentV9_6) works at run time, but pyright rejects it: Second argument to "isinstance" must be a class or tuple of classes, with the detail TypedDict class not allowed for instance or class checks. Against the latest release it does not even work at run time: IDFDocumentV26_2 is IDFDocument, the class of every document, so isinstance(doc, IDFDocumentV26_2) is True for a 9.4 model too.
    • case IDFDocumentV9_6(): in a match also works at run time, and pyright rejects it too: TypedDict class not allowed in class pattern.

    Verify the result¶

    Run pyright over the module. Then pass it a model of the oldest and the newest release you claim to support; the type checker cannot see what get_collection and item access such as zone["ceiling_height"] return. To lint the doc.add(...) calls pyright cannot check, run idfkit check with the same releases as targets; see how to check idfkit code.
